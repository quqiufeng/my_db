Input IDs are particularly useful in this example, as without ID values, any errors would simply list “Redis” as the issue, even though we have two Redis inputs. Naming these inputs will help us address problems in the future or analyze network performance for each input. 
 Both inputs connect to localhost on port 6379, which uses the SSH tunnel to transparently link them to the Redis server on the distant end. Redis uses a strong random password to authorize connections, and both inputs specify   that password  ❶ . The channel input  ❷  connects to the channel  key , or name,  mychannel   ❸ . The list input  ❹  specifies its key,  mylist , to pull queued data.
